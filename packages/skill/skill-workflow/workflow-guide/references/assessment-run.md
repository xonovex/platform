# assessment-run: Assess an Exact Workflow Result

## Core workflow

1. Resolve any canonical workflow result at the requested exact native revision plus its relevant source/evidence references.
2. Resolve applicability before asserting a framework, policy, risk, security, accessibility, AI, supply-chain, privacy, legal, or other criterion. Pin criterion identifiers and versions; mappings do not prove equivalence, certification, or compliance.
3. Apply [assurance-contracts.md](assurance-contracts.md) to select deterministic tools, scanners, external systems, bounded model/agent assistance, and human or qualified assessors with explicit origins and independence.
4. Run applicable criteria, preserve per-evaluator native evidence, and distinguish pass, fail, not applicable, not evaluated, unknown, partial, stale, and exception states.
5. Re-resolve the subject, policy/profile, evaluator, environment, and evidence revisions before disposition. If a binding value changed, publish a stale/incomplete result or re-run; never carry a pass forward silently.
6. Publish an Assessment result with exact subject, criteria/framework and versions, applicability, method, evaluator origins/qualifications, evidence, results, gaps, limitations, and follow-up capabilities.

Assessment is generic. If the subject is a deliverable and the intent is code/design findings or environment testing, preserve Review or QA as the focused result kind rather than disguising it as only Assessment.
