# acceptance-validate: Assemble Acceptance Evidence

## Core workflow

1. Resolve the exact Deliverable Publication reference/revision, intended target,
   acceptance criteria, profile/policy versions, and required actor or independence rules.
2. Collect fresh provider-native Review, QA, Assessment, Inventory, and other required
   evidence. Keep each origin, exact revision, evaluator/environment version, outcome,
   limitation, and expiry independent.
3. Apply the selected acceptance method and report each criterion as satisfied, failed,
   partial, stale, not applicable, unknown, or not evaluated. Do not coerce missing,
   skipped, neutral, cancelled, or timed-out evidence to passing.
4. Allow bounded model or agent assistance only for sourced summaries and gap detection;
   mark it advisory and validate every cited reference.
5. Re-resolve the deliverable, target, evidence, policy, and profile bindings. If any
   required value changed, publish a stale/incomplete validation rather than carrying a
   previous result forward.
6. Publish an advisory evidence package with exact bindings, per-criterion findings,
   sources, gaps, limitations, and the human role required for the separate Acceptance
   decision.

This operation cannot sign off, authorize Integration, or fabricate accountable authority.
An unavailable explicitly selected provider fails visibly instead of falling back locally.
