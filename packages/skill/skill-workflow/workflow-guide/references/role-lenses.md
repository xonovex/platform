# Role Lenses

A role lens is an optional convenience that proposes perspectives, criteria,
evidence, vocabulary, and communication depth. Resolve the proposal through the same
assisted process as any other suggestion.

Illustrative mappings:

| Familiar lens | Possible proposals                                       |
| ------------- | -------------------------------------------------------- |
| Product       | User value, scope, acceptance coverage, outcome evidence |
| Design        | Usability, accessibility, content, research evidence     |
| Engineering   | Correctness, maintainability, compatibility, operability |
| Quality       | Behavior coverage, reproducibility, evidence quality     |
| Security      | Threat, privacy, abuse, auditability                     |

Role names do not select an operation sequence, executor identity, provider, owner,
permission, or authority. They do not force a handoff or claim an organizational
responsibility.

For each proposal, record its role-lens source and reason. Perspective proposals may
be used for advisory questions under assisted resolution. Criteria remain advisory
until explicit caller acceptance or authoritative policy makes them binding.

Prefer direct repeatable perspectives when the caller already knows the concerns.
Do not create persona bundles that combine domain knowledge, procedure, permissions,
and communication in one selection.
