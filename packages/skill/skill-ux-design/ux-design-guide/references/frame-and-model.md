# Frame and Model

## Design Frame

Start from research-backed user needs and the product outcome. Record the affected
population, current journey, desired progress, environment, channels, policy and
content constraints, accessibility needs, technical constraints, exclusions, and
assumptions still needing evidence. Do not translate a requested screen directly into
a flow.

## Journey and State Model

Describe the end-to-end service boundary before individual screens. Map entry points,
tasks, decisions, information dependencies, channel or actor handoffs, completion, and
re-entry. For each interaction, enumerate normal, empty, loading, validation, partial,
error, timeout, permission, cancellation, recovery, and completed states.

Model content purpose and hierarchy with the interaction. Include keyboard order,
focus changes, announcements, zoom/reflow, reduced motion, input alternatives, and
error recovery as design inputs; accessibility is not a later annotation pass.

## Alternatives

Generate at least two meaningfully different approaches when the decision is
consequential. Compare them using the same criteria:

- user need and whole-journey coherence;
- comprehension and task effort;
- accessibility and inclusion;
- policy, privacy, and safety;
- technical and operational feasibility;
- reversibility and evidence required.

Preserve rejected alternatives and the evidence or constraint that rejected them.
