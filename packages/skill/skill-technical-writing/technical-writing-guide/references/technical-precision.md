# technical-precision: Preserve Exact Technical Meaning

## Preserve Technical Names

- Keep exact identifiers, paths, commands, configuration keys, units, protocol names, and error text when they affect the result.
- Define unavoidable jargon at first use. Do not replace a precise term with a looser synonym.
- Distinguish components that have similar names. Do not shorten a name when the shorter form can identify more than one thing.

## State Conditions and Comparisons

- Keep a condition beside the behavior it controls.
- State the baseline, environment, workload, and measurement period needed to interpret a number.
- Keep a limit or missing measurement beside a recommendation when it can change the decision.
- Separate observed behavior, verified cause, hypothesis, and prediction.

## Keep Instructions Exact

- State commands and values exactly when a reader must reproduce an action.
- Name the required state before an action and the observable result after it.
- Do not invent an owner, deadline, risk rating, confidence value, or operational step.

## Check

- Are identifiers, units, values, and comparisons unchanged?
- Can the reader distinguish facts, inferences, and unknowns?
- Does each condition still control the correct behavior?
- Can the reader verify the conclusion from the evidence that remains?
