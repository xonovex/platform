# Early Lifecycle Result Contract

Discovery, Research, Formulation, Experience Design, Solution Design, Decision, and Planning keep stable semantic results while methods, executors, and persistence vary independently.

## Axis resolution

Resolve each axis independently in this order: explicit command argument, selected workflow profile, project instructions, unambiguous environment detection, axis-specific default, then a visible request for selection. Resolution yields a requested value, not a grant — an `--executor` request additionally passes the validation in Executor selection below. Never infer a method from a provider or a provider from a native-reference shape.

- **Method** — neutral is the default. User stories, BDD, example mapping, user research, accessibility review, architecture review, and other installed skills are selectable capabilities, not prerequisites.
- **Persistence** — in-session, file, hosted, database, or other persistence is caller-selectable. When a provider is explicitly selected, use its real capabilities and fail visibly instead of silently changing providers.
- **Profile** — may omit Experience Design or Solution Design, but cannot erase an included capability's independent result.

## Executor selection

Every early lifecycle operation selects from `deterministic`, `model`, `agent`, `human`, and `external`. These record how a result originated; they do not grant authority.

Qualification is an attribute of a human actor record, not a class. A profile that requires regulated, safety, security, privacy, accessibility, architecture, or other role-bound judgment binds its Decision to a `human` whose record carries the matching qualification; a model or agent cannot supply it, and an unqualified human does not satisfy it.

Escalation changes the executor, not the result kind. Record executor origin, bounds, material tool/data use, and limitations in the native result.

## Result lifecycle

1. **Resolve** every input from its provider context and opaque native reference; verify native revision and freshness.
2. **Create** one operation-owned result with sources, scope, assumptions, outcome, gaps, executor origin, and relevant context.
3. **Critique** the exact native revision in fresh independent context. A critique publishes a separate evidence/result reference and does not edit or accept the subject.
4. **Revise** from explicit feedback and critique references. Publish a new native revision, relate it to the prior revision, preserve unresolved items, and never overwrite history invisibly.
5. **Accept** only through the actor and authority required by the profile. Bind the decision to the exact revision; a model may prepare a brief but cannot claim human or qualified authority.
6. **Resume** using the selected persistence model. Resolve provider context plus native reference and reconstruct only the operation state needed to continue.

Evidence supports a result; it does not decide. Authority permits a decision; it does not prove the evidence. Enforcement applies a policy decision; it is not the decision itself.

## Publication response

Return the identifiers supported by the selected persistence model: provider context when applicable, native reference, native revision when available, result kind, source references, available follow-up capabilities, and limitations. Do not require a universal persisted envelope.
