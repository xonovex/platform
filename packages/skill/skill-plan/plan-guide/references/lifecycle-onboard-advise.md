# lifecycle-onboard-advise: Recommend an Early-Lifecycle Composition

Advise without installing, configuring, authorizing, or applying changes.

## Core workflow

1. Resolve the selected workflow profile and discover available lifecycle capabilities, installed skills, provider adapters/capabilities, executor classes, workspace facts, and governance/environment modules.
2. Compare profile requirements with actual versions, editions, permissions, data flows, native-reference/revision strength, policy intents, authority needs, and fresh-context support.
3. Recommend each independent axis: included/optional capabilities, neutral or specialist methods, skills to load/install, result providers, executor bounds, policy/governance evidence, and environment modules.
4. Distinguish required, recommended, optional, incompatible, unavailable, and unsupported items. Preserve workflow-only and advisory-only compositions when profile-valid.
5. Preview exact native changes only for optional follow-up onboarding: packages/modules, versions, permissions, secrets/network/data access, expected evidence, verification, rollback, and drift behavior.
6. Publish or return an advisory result with provider-native evidence references and limitations; stop before approval or apply.

Apply [early-lifecycle-contracts.md](early-lifecycle-contracts.md). Do not infer provider support from names, treat installation as enforcement, or make user-research/accessibility/BDD/Git/provider skills universal prerequisites.
