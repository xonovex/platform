# Follow-up seed template

Paste one block under `# Follow-up seeds` of the close-out record for each coherent chunk of remaining work, and replace every angle-bracket placeholder. A seed is raw material for the next plan, not a plan: **writing-plan** or **researching-change** turns it into one for a new change.

```markdown
## <Seed name as a short noun phrase>

- Objective: <One sentence stating the outcome the chunk delivers.>
- Why it exists: <The open criterion, gate or finding it answers. Say so when this work was attempted and did not land: that signals it needs planning, not improvisation.>
- Start: <now, after a named gate or decision, or independent of the other seeds>

### Current state, evidenced

<What is true now, each fact with the command or file it was read from and the revision.>

### What is open

<The questions planning must settle, each as a question.>

### Known traps

- <A failure mode already met, and how it showed itself.>

### Success criteria sketch

- <An observable condition and the means that checks it.>

### Validation

<The commands or checks that will show the criteria hold.>

### Gated on

<The gate or decision and its owner. Write "Nothing." when none.>

### Skills to consult

<Installed skill names the future plan should carry in `skills_to_consult`.>
```

## Fill in

- One seed for each coherent chunk: work that shares an outcome, an owner and a gate. Do not merge unrelated leftovers, and do not split one outcome across seeds.
- When there is more than one seed, put this table above them:

| Seed   | Start   | Gated on | Independent of |
| ------ | ------- | -------- | -------------- |
| <name> | <start> | <gate>   | <seeds>        |

- `Current state, evidenced`: facts re-derived in this run. A figure from a document that disagrees with the code is reported with both values.
- Leave out `Skills to consult` when the plan's own list already covers the chunk.
